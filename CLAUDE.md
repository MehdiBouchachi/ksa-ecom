# Commerce app — persistent instructions (PostgreSQL, NO Supabase)
One pnpm monorepo; **one deployed Next.js App Router full-stack app** on Hostinger Business/Unlimited. TypeScript, Tailwind CSS, shadcn/ui, Zod. **PostgreSQL** via Drizzle ORM + `pg` (`drizzle-orm/node-postgres`); Auth.js Credentials with DB users and secure HttpOnly sessions. Arabic RTL first; English-ready. No Supabase, no MySQL/MariaDB, no separate API server, Redis, job-queue workers, or assumed PostgreSQL process on managed Hostinger.

**Docker (primary, approved by the owner 2026-11-09):** one image + compose (`secrets`→`db`→`app`→`cron`, `caddy` in prod) runs locally with zero config and on a Hostinger VPS (`scripts/deploy.sh`, `.github/workflows/deploy.yml`). Secrets are generated into private volumes; third-party creds only in the server's git-ignored `.env.production`. Never commit secrets or bake them into the image. The non-Docker Business path below stays supported.

**Deployment reality:** Hostinger Business/Unlimited runs Next.js, but cannot run a native PostgreSQL server. Use **external managed PostgreSQL not Supabase**, selected/approved by merchant, connected through `DATABASE_URL` with verified TLS/SSL; alternatively Hostinger VPS can run both app+Postgres but would change the hosting plan. Keep one application deployment. Never assert DB is included in the Business subscription.

**Non-negotiable:** (1) SKU = product+color+size; (2) retail and wholesale quantity tiers share stock; (3) PostgreSQL ACID transaction with `SELECT ... FOR UPDATE` inventory row locks prevents overselling; (4) validated PSP webhooks/idempotency; (5) distinct order/payment/shipping states; (6) Admin manages all users, Manager must not see user lists/admin accounts and sees order-specific delivery data only; (7) server RBAC and owner-scoped DB queries on every request; (8) server recalculates prices/tax/stock; (9) merchant confirms ZATCA/PDPL and disclosure requirements. No default DB RLS assumed; Auth.js ownership enforced server-side.

**Token discipline:** read `docs/STATE.md` and `docs/TASKS.md`; for current task read ONLY referenced specs and affected code, not all docs or prior large PDF. One task/session, small patches/targeted tests, update STATE; final reply <=8 lines including changed files, tests, blockers, next task.

**Operations:** never persist customer uploads in Hostinger deployment/public_html directories; use approved durable object storage (e.g., Cloudflare R2) with backup/redeployment checks. PSP/Aramex sandbox until approved; never invent merchant tax facts, prices, credentials. Store secrets server-only; ensure external DB connections are TLS-protected and pool/concurrency bounded.
