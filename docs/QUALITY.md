# Non-functional, legal & release quality
- **SEO:** server-rendered indexable public product/category/brand/collection/about pages; canonical URLs, unique titles/descriptions, robots/sitemap, semantic HTML, `Product`/`Offer` JSON-LD using truthful price/stock, Arabic metadata, breadcrumbs, alt text. No index on checkout/account/admin/staging and duplicate filtered URLs. Target Lighthouse SEO 100 under controlled run, release >=95; ranking/100 score not guaranteed.
- **Performance:** mobile Lighthouse Performance >=90 target, LCP<=2.5s, INP<=200ms, CLS<=0.1 (p75 where tracked); public read endpoint p95<=500ms; DB write p95<=1s excluding external PSP/Aramex; checkout prepare p95<=2s at stated moderate load. `next/image` or CDN sizing, deferred third-party scripts, lean React payloads and DB indexes. Never cache personalized pages or authoritative available stock.
- **Accessibility:** aim WCAG 2.2 AA, accessible color/size selectors, keyboard/focus labels, Arabic RTL, English-ready; test 360/390/768/1024/1440 layouts, no horizontal scroll.
- **Security:** Auth.js sessions with HttpOnly/Secure/SameSite cookies, strong password hashing and rate limiting; verify user and role in DB on each protected request; do not assume PostgreSQL RLS. Every customer query constrains `user_id` or joins to authenticated owner. CSRF/origin protection for browser mutations, Zod input validation, webhook authenticity verification, least-privilege PostgreSQL DB credentials, backup restore drill, MFA for admins if implementable, audit financial/stock/role changes, redact PII/secrets. No credentials in `NEXT_PUBLIC_*` variables.
- **Hosting constraints:** Hostinger managed Node.js app is a single process; no perpetual workers, Redis, custom service ports or production Docker. Use signed cron endpoints. Hostinger deployment folders and `public_html` are overwritten on every deployment: durable uploads need verified separate storage and backups.
- **Merchant/legal obligations:** verified public merchant info/contact, shipping/returns/refund policies, transparent prices and VAT when applicable. Confirm merchant VAT and ZATCA e-invoicing Phase 1/2 applicability before launch; a generic order email is not a compliant invoice. PDPL consent/notice, retention, access/deletion workflow, processors, hosting region/cross-border transfer assessment. Legal/accounting review required; do not claim automatic legal certification.
- **Acceptance:** see `ACCEPTANCE.md`; launch requires stock-race, payment, Aramex sandbox/actual account and backup/restore tests plus verified merchant details. Provider activation/eligibility are external prerequisites.
